# QalaAccess AI — Every Journey Matters

**AI-Powered Inclusive Urban Navigation for Kazakhstan** · университетский прототип для курса PLS 419 «An AI Answer for Kazakhstan».

> «The shortest route is not always the most accessible.»

Сайт: **https://aushenova.github.io/psir-project/** (после включения GitHub Pages, см. ниже).

---

## 1. Как открыть сайт на своём компьютере

1. Откройте папку проекта.
2. Дважды щёлкните по файлу **`index.html`** — он откроется в браузере (лучше Chrome).
3. Для карты нужен интернет.

**Если на карте написано «Access blocked»:** нажмите значок слоёв в правом верхнем углу карты (**Map style**) и выберите *OpenStreetMap France* или *Esri Streets*. Выбор запомнится. На опубликованном сайте (github.io) такой проблемы обычно нет.

## 2. Что есть на сайте

Сайт — **одна длинная страница** (`index.html`) в журнальном стиле. Сверху заголовок, ниже **закреплённое меню в одну строку**: при прокрутке оно остаётся вверху и подсвечивает текущий раздел.

| Блок | Что внутри |
|---|---|
| Заголовок + «1/112» | Название, слоган и главная цифра: только у 1 из 112 переходов в центре Астаны есть данные о звуковом сигнале. |
| **01 The Problem** | Кто затронут, масштаб, динамика, социально-научный вопрос. |
| **02 Background & Data** | Таблица «кто что измеряет», 2 собственных графика из реальных данных, пробелы и надёжность данных. |
| **03 Current State of Research** | 9 научных источников по 4 подходам и пробел в исследованиях. |
| **04 AI Solution & Its Cost** | Решение, 2 реальных кейса, «счёт» в виде чека (экология, экономика, труд, политика, этика данных) и вердикт. |
| **05 Route Planner** | Выбор A и B на реальной карте Астаны и потребностей. Кратчайший маршрут (серый пунктир) и маршрут под потребности (бирюзовый); для каждого барьера — объяснение простыми словами, **почему он мешает человеку**. |
| **06 Report a Barrier** | Отметить помеху: место → тип → описание и фото. Помеха **сразу** появляется на карте как *Verified*, маршрут в блоке 05 пересчитывается. |
| **AI Transparency** | Заявление о прозрачности ИИ: что сделал ИИ (код, данные, маршрутизация, поиск источников и черновики) и что сделали вы. |
| **References** | Общий список всех источников. |

### Честность данных
- **Реальные данные:** улицы, дорожки, переходы и 56 лестниц из OpenStreetMap (район Нуржол бульвара, скачано 23.11.2026).
- **Синтетические данные:** 12 примеров отчётов и атрибуты 5 переходов (звуковой сигнал, тактильная плитка и т.п.) — везде помечены *Synthetic sample / Synthetic demo*.
- Неизвестное **никогда** не считается доступным; маршрут помечен «NOT verified».
- Отчёты хранятся только в этом браузере (localStorage). Кнопка **Remove my reports** на странице Report a Barrier удаляет ваши отчёты (примеры остаются).

## 3. Сценарий презентации (~5 минут)

> Перед презентацией: Report a Barrier → **Remove my reports** (нажать два раза), чтобы убрать тестовые отметки.

1. Открыть сайт: заголовок, слоган и большая цифра **1/112** — с неё удобно начать рассказ о проблеме.
2. В меню нажать **05 Route Planner** → Start: *Keruen Mall*, Destination: *Parliament (Senate)* → ✓ **Wheelchair** → **FIND ACCESSIBLE ROUTE**.
   Серый маршрут 1,51 км проходит через 7 лестниц (данные OSM), бирюзовый 1,91 км — без лестниц. В объяснении: «A wheelchair cannot go up or down steps».
3. Снять Wheelchair, поставить ✓ **Blind or visually impaired** — маршрут сам пересчитается (2,06 км). В объяснении: «Sound signal is not working — a blind person cannot hear when the light turns green…».
4. Честное сообщение: Start *Baiterek Plaza*, Destination *Khan Shatyr*, ✓ Wheelchair → «**No verified accessible route is available with the current data.**» (в OSM к входу ведут только лестницы — пандусы не нанесены на карту; это и есть проблема данных).
5. Вернуться к Keruen → Senate с Wheelchair, нажать **FIND ACCESSIBLE ROUTE**. В меню нажать **06 Report a Barrier** — на карте видна линия вашего маршрута. Нажать на бирюзовую линию → **Blocked sidewalk** → **Submit report** → «Your report has been added to the map as verified.»
6. Нажать **See the effect in the route planner** — маршрут перестроится, появится зелёный блок «The route goes around reported barriers: Blocked sidewalk — the sidewalk is blocked, so a wheelchair cannot pass…».
7. Нажать на значок 🚧 на карте — откроется описание и объяснение для каждой группы людей.
8. Через меню пройти **01 → 04**: на 02 показать собственные графики, на 04 — «чек» и тёмный блок вердикта. (Порядок можно поменять: сначала исследование 01–04, потом демо 05–06.)
9. Финал: «An accessible destination is not enough if the journey itself is inaccessible.»

**Запасной план:** если в аудитории нет интернета, карта не загрузится — заранее сделайте скриншоты каждого шага.

## 4. Публикация на GitHub Pages (один раз)

1. Откройте https://github.com/aushenova/psir-project
2. **Settings** → слева **Pages**.
3. **Source:** *Deploy from a branch*. **Branch:** `main`, папка `/ (root)` → **Save**.
4. Репозиторий должен быть **Public** (Settings → General → внизу *Danger Zone* → *Change visibility*), иначе бесплатный Pages не работает.
5. Через 1–2 минуты сайт откроется по адресу https://aushenova.github.io/psir-project/

## 5. Тексты разделов

Тексты четырёх разделов написаны с помощью ИИ на основе реальных источников (около 3 400 слов основного текста; вместе с заголовками, таблицей и подписями — около 3 580, в пределах 3 200–3 600).

**Что нужно сделать вам перед презентацией:**
1. Прочитать все четыре раздела и открыть каждую ссылку в списке **References**, чтобы убедиться, что источник говорит именно то, что написано.
2. Отредактировать текст своими словами там, где хотите.
3. Прочитать блок **AI Transparency** и убедиться, что он точно описывает вашу работу с ИИ (он должен совпадать с AI Process Log).

**Как редактировать:** на github.com откройте `index.html` → значок карандаша ✏️. Каждый раздел начинается с комментария вида `01 THE PROBLEM`. Абзацы находятся между `<p>` и `</p>`, источники — в строках `<li> … </li>` в блоке References. Нажмите **Commit changes** — сайт обновится через 1–2 минуты.

## 6. Техническая часть (для преподавателя)

- Чистые HTML/CSS/JavaScript, без сборки. Шрифты Space Grotesk / Newsreader / IBM Plex Mono (Google Fonts). Карта — Leaflet 1.9.4 (CDN), подложка OpenStreetMap (есть переключатель на запасные).
- `tools/build_graph.py` — превращает выгрузку OpenStreetMap (Overpass API) в граф `js/data/graph.js` (2 587 узлов, 3 762 сегмента).
- `js/router.js` — алгоритм Дейкстры. Лестницы и высокий бордюр — непроходимы для коляски; переходы без работающего звукового сигнала избегаются для незрячих и т.д. Внутренние веса пользователю не показываются — вместо них объяснение простыми словами.
- Каждый сегмент хранит: ID, геометрию, длину, тип, покрытие, лестницы, бордюр, уклон, тактильную плитку, звуковой и визуальный сигнал, источник данных.
- Данные карты © OpenStreetMap contributors, ODbL.
